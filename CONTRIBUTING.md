# Contributing

Open a focused change with its behavior, security impact and relevant evidence.
Use synthetic examples. Never submit a real deployment's topology, keys,
policies, inventories, logs or state.

Run the unit and native checks described in the README. Boot, storage, signing,
update and policy changes also need the affected qualification gates. Preserve
third-party licenses and source/patch attribution. Changes to dependencies,
workflows, exceptions or trust rules require review; automation proposes these
changes and does not approve them.
